# 样式校准与交付门禁

## 从真实失败中改变处理顺序

扫描 PDF 的隐藏 OCR 曾把同一名单的三字姓名报告为约 9.8 pt、两字姓名报告为约 15 pt。逐段采用该字号，再缩放到 OCR 框宽，生成了大小不一的字形。OCR 还把楷体引文标成普通宋体，小面积取色使同一红色标题混入黑色编号。这里的约束针对这些实际失败，不是要求所有书采用相同字体或字号。

在批量重建之前：

1. 按原图识别本书实际出现的样式角色，至少覆盖正文和发现的特殊角色；已认可样张是首选校准依据，保留其摘要。用户要求的页范围不因采样扩大。
2. 校准正文、标题、页眉、目录层级、引文、名单、脚注标记和数字各自的字体/字重/字号/颜色/基线。不要直接把 OCR 的 SimSun/SimHei 等标签视为原版字体。
3. 从多枚完整字形的可见墨迹与基线确定字号，再结合所选字体墨迹度量试排；不把 word bbox 高度或宽度当 em。校准结果用稳定 `style_id` 复用，OCR 框只辅助定位。
4. 用角色区域检查结果，原图与试排放大并排。名单要同时有两字和三字项目；正文要包括引文、标点与脚注；只在原书存在这些角色时检查。
5. 校准未通过时修正共享样式，再扩展批次。不能先生成整书，再把大批异常解释为“字体近似”。这一步是内部质量控制，不要求重复向用户申请已授权的操作。

## 字宽、字距和颜色分开处理

- 两个字占三个字的列宽：保持同字号、字重和字形比例，在字间分配空隙。对齐的是名字的布局宽度，不能把两个字都放大到 1.5 倍。
- 窄标点和横线：字号继承所在文本角色，位置按其墨迹校准；破折号范围与字形宽度不能直接变成大号字体。
- 水平压缩不能成为排版默认手段。明显偏离正常比例时先查字体、OCR、缺失空格和段落边界；必须保留原版特殊变形时留下原图证据。把缩放简单限制在 0.35—2.5 之间仍可能严重变形。
- 引文楷体、标题粗体、页眉小字分别建角色；局部字号微差不应产生几百个伪样式。
- 对完整标题/行的有效墨迹取色，使用足够分辨率，剔除纸底、邻近红线与图标。确认同一标题是红色后，编号和标点继承该角色；不要因单字红像素不足改成黑色。
- 生僻姓名必须同时在内容清单和可见文字中出现。OCR 漏掉的名字可能留在底图里，整页看似完整却没有被文字化。

## 可执行的区域样式检查

复制 [style-plan-template.json](../assets/style-plan-template.json) 并填写。空模板不会通过。计划以原图/认可样张校准，不能从待验收输出的字体统计直接生成“期望值”。

每个 region 包含 `id`、`role`、`output_page`、显示页坐标 `bbox`、`basis` 和 `expected`。`expected` 指定 `size_pt: [min,max]`、PDF 实际字体名列表 `fonts`、`color_rgb`、`color_tolerance`；可选 `nonspace_chars` 是区域应有的非空白文字对象字符数。区域包含脚注等不同角色时，应拆分区域，不扩大字号范围掩盖差异。

所有 tolerance 都是具体字体替代和扫描证据支持的容差，不是通用 PDF 质量标准。`nonspace_chars` 只能提示缺少/多出文字，数量相等不证明内容或阅读顺序正确；连字和组合文字先核实工具的码点表示，再决定是否设置该数值。

```bash
python scripts/pdf_style_check.py rebuilt.pdf --plan source/style-plan.json --report work/style-check.json
```

脚本检查区域内可见候选字符的字号、字体、颜色和可选数量。字形可能被遮挡，横向变形及未列出的区域也不保证正确。计划写得宽泛或错误时，脚本不会替你知道原书的正确样式。

## 交付证据格式 review-v2

复制 [review-template.json](../assets/review-template.json)。本格式为本项目约定，不是 Agent Skills 标准。

- `source_sha256`、`rebuilt_sha256`：当前文件的完整摘要；`source_pages` 是按输出次序排列的物理源页号。
- `pages`：每个输出页恰好一条，含 `output_page`、`source_page`、`status: reviewed`、`notes` 和检查结论。`checks.content/layout` 必须为 `pass`；`images/math` 可为 `pass` 或有事实依据的 `not-applicable`。
- 每页 `full_page` 和 `details` 保存实际检查过的全页图与局部图引用。全页图不能重复当局部图，联系表不能复用成多页独立检查。门禁比较解码后的图像内容，改名或重新编码不能变成新证据；原书若有完全重复的空白页，检查图附独立源/输出页号标识，不修改交付 PDF 的空白页。`notes` 写实际发现和修正，不以“渲染成功”代替。
- 证据引用格式统一为 `{ "path": "work/evidence/p001.png", "sha256": "..." }`，路径相对 review JSON 所在目录，只允许该任务目录内文件；不嵌入个人绝对路径。生成后的证据及输出改变时需重新复核和更新摘要。
- `style_plan` 指向独立校准计划的同类文件引用；门禁会读取计划并对当前 PDF 重跑检查，不接受预写的通过状态。
- `structure.navigation.status` 为 `verified`，含实际目录与跳转复核证据。存在标签时 `structure.tags.status` 必须是 `new-content-verified`；仅复制入口、`preserved` 或 `pending` 不能通过。存在可选图层时 `optional_content.status` 必须是 `verified`。两份文件均不存在该结构时填 `not-present`。
- `unresolved` 必须明确列出，尚有内容或结构问题就保留，不能为了通过删除。

## 例外必须有边界

`exceptions` 每条包含 `output_page`、`kind`、`reason`、`evidence`。仅接受 `blank`、`artwork`、`verified-background` 三类；不能使用“全部问题可忽略”的通用 waiver。前两类允许该页缺少可见文字或保留大面积图像，前提是已按原图和用户要求确认其确为可保留范围，不能把普通扫描正文归为 artwork。

`verified-background` 只允许保留经过核实的底图，另需 `text_removed_diagnostic` 文件引用：单独显示底图及保护区域，检查无应重建正文残影。其他结构问题不会因此消失。

隐藏文字、未知 Unicode、字体程序问题、错误书签或失效链接不能靠例外字段改判通过；修正后重新检查。真实装饰图像中的旧隐藏 OCR 可去除，保留图像外观；不能以保留标签为由留着旧 OCR 并叠加一套新正文。

```bash
python scripts/pdf_delivery_gate.py input.pdf rebuilt.pdf --source-pages 1-10 --review review.json --report work/delivery-gate.json
```

退出码 `1` 表示阻止完成交付，`2` 表示工具未正常完成，均不能声明完整重建。`0` 仅表示当前有限检查和证据记录一致；它不是 OCR/视觉/标签正确性的证明，也不能证明填写者真的完成了目视校对。必须结合已完成的实际复核。旧 review-v1 的自由文本“完成”声明不能授权跳过新门禁。

## v1.2 的区域边界检查

`style-plan-v1` 可在 `expected` 添加 `content_bbox: [x0, y0, x1, y1]`，限制选中字符的完整度量框。它必须位于该区域的选择 `bbox` 内；选择范围应包含可能溢出的行尾，不要只框住正确字符。使用正文行带和较宽的横向选择范围，配合 `nonspace_chars`，避免字号正确却漏查行末。此检查不是像素墨迹检测；跨角色、行内分式或旁边插图需要按实际结构拆分计划。参见 [混排与几何流程](pilot-and-mixed-math.md)。
